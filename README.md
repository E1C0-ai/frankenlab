# FrankenLab — 一句话，开一家一站式小店

Kiroween 2026 · Frankenstein 类别参赛作品 · 截止 2026-12-04 14:00 PT（北京时间 2026-12-05 06:00）

> ⚠ 本项目仅黑客松模拟演示，无真实交易能力，不会产生真实订单、不会扣款。全部数据仅保存在浏览器本地，不上传服务器。

## 痛点
普通人想开店，脑子里只有一个想法，既要设计门店点单系统，又要整理要买的设备物料、对比新品二手成本，门槛很高。

## 是什么
输入一句话，同时产出两件东西：

① **可交互模拟店铺 App**：可以点单、购物车、接单记账、管理订单；
② **开店配套采购方案**：设备清单，新品/二手平替对比，电商搜索入口。

输入“开一家奶茶店”，一分钟就能点单、下一单、看到账本，再把采购清单复制走。

## 怎么用
双击 `index.html` 就能打开，或 `python3 -m http.server 8000`。点 3 个示例按钮任意一个（“开一家奶茶店”“美甲工作室”“少儿钢琴教室”）就能一键生成整套店铺，不用手动输入。

## 功能
- 识别店铺类型自动生成店铺（奶茶 / 美甲 / 钢琴教室 / 咖啡 / 花店 / 宠物 / 通用），店名均为虚构，已过滤真实连锁品牌名（如蜜雪冰城等不会出现）。
- 店面点单、购物车改数量；下单结算生成订单；订单管理完成/取消；账本统计总收入、订单数、热销商品（柱状图一眼看懂）。
- 本地存储开店待办（打勾，刷新不丢）。
- 采购清单：物品、规格、数量；新品/二手平替两套价格，自动算模拟节省；生成淘宝/京东搜索链接（**只是搜索页链接，不是具体商品链接**）。
- **没有一键购买**：评审后已删掉模拟一键购买、假账号、假订单号那套。替代做法是勾选采购项，一键复制导出采购清单文本，用户自己去电商粘贴搜索，彻底避开仿交易界面合规风险。

## 价格免责（UI 上每处都有，不只写在这里）
- 采购清单每一个区块都有小字提示：价格仅模拟参考，不保证准确，不作为实际采购依据。
- 自动算的“省多少钱、总节省”都标注：节省金额仅为模拟估算，不是实际可拿到的优惠。
- 部分价格有公开来源（如奶茶封口机、制冰机参考区间，来源见代码注释），其余一律写“参考区间，未核实”，不写成确定价。所有价格都是参考价、会变，以实际购买时为准。

## 隐私：数据只在浏览器本地
- 全部运算在浏览器本地；姓名、电话、订单、待办、采购勾选只存在浏览器 localStorage，绝不向后端上传，不回传服务器。
- 结算页明确提示：演示用，请勿填写你的真实私人手机号。姓名、电话仅保存在浏览器本地，不会发送出去。
- 点“重置整个店铺”可以一键清空全部店铺、订单、账本、待办、采购清单，方便多次演示。

## 为什么是 Frankenstein
把几件不相干的东西缝进一个应用：点单系统 + 订单账本 + 采购清单 + 省钱对比 + 搜索入口。每一件单独都能用，缝在一起才叫一站式开店模拟。

## 怎么用 Kiro 做的
- Spec-driven：先写 `.kiro/specs/frankenlab/requirements.md`（需求）、`design.md`（设计）、`tasks.md`（任务），再按任务写代码，不是先写代码再补文档。
- Steering：`.kiro/steering/product.md`（隐私优先、开箱即用）、`tech.md`（零依赖、零构建）、`structure.md`（目录约定）。
- Hooks：`.kiro/hooks/test-on-save.json` —— 保存 `src/app.js` 后自动跑测试。
- MCP：`.kiro/settings/mcp.json` 已留好配置位（本项目不需要外部 MCP，生成全在本地，所以是空配置，如实说明）。

## 测试
`node test/app.test.js` —— 27 个检查全过（类型识别、品牌过滤、搜索链接、节省计算、导出免责、账本、确定性等）。

## 未来可扩展
本项目结构可扩展为 Jira 原生插件 / 真实店铺系统：把本地订单、账本、采购清单接进真实后台即可，但当前版本刻意不接任何后端、不做真实交易。
